# PARA 和 MOC 联用组织笔记

PARA 和 MOC 可以一起用。

我的理解是：PARA 负责给笔记一个阶段位置，MOC 负责把散落的笔记重新组织成主题路径。

## PARA 管状态

PARA 的四类可以理解成状态：

- Project：正在推进、有明确结果的事情
- Area：长期经营、需要持续关注的领域
- Resource：以后可能复用的资料、方法和概念
- Archive：暂时不主动维护，但还可以搜索和引用的内容

这种结构的好处是轻。它只给知识库一个大方向，不会逼着每条笔记都进入复杂分类。

## MOC 管主题

MOC 是内容地图。

文件夹能告诉我“这条笔记现在放在哪里”，MOC 能告诉我“这些笔记之间有什么关系”。

一个 MOC 可以做几件事：

- 聚合某个主题下的关键笔记
- 写清楚主题边界
- 暴露还没补齐的知识缺口
- 给未来写文章留下目录雏形
- 给公开站点提供入口

MOC 可以嵌套。大 MOC 负责主题，小 MOC 负责局部问题，底层再连接原子化卡片。

## 两者怎么配合

PARA 更偏全局整理，MOC 更偏局部组织。

举个例子：一批关于 Obsidian 的笔记，可以放在长期关注的 Area 里；但如果我要写“Obsidian 插件体系”，就需要一个 MOC 把插件、工作流、搜索、发布、维护这些内容串起来。

所以我的默认规则是：

- 文件夹只粗分
- MOC 承担主题组织
- 链接保留真实关系
- 新笔记尽量接到已有 MOC 或项目

这样能保留基本秩序，又不会让分类消耗太多精力。
