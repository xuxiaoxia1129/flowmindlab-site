# MOC、PARA 与 ACCESS 如何分工

知识库最容易陷入两个极端：完全不整理，最后只能靠搜索；或者过度分类，每写一篇笔记都要先判断它属于哪里。

我更倾向于混合使用三种结构：PARA 提供大方向，ACCESS 提供工作区，MOC 提供主题导航。

## PARA 负责阶段

PARA 把内容分成 Project、Area、Resource、Archive。

我更愿意把它理解成状态管理，不当成严格分类法：

- Project：正在推进、有结果要求的事情
- Area：长期经营、需要持续关注的领域
- Resource：可复用的资料、方法、概念和参考
- Archive：暂时不主动维护，但仍然可以搜索和引用的内容

它的优点是轻量。一个笔记不需要永久待在某个位置，它可以随着状态变化移动。

## ACCESS 负责工作台

ACCESS 更像 Obsidian 知识库里的工作台设计。

我主要借用其中几个概念：

- Calendar：承接每日想法和临时记录
- Cards：沉淀原子化想法
- Sources：保存阅读、文章、书籍等外部材料的消化结果
- Spaces：承载项目、领域和较大的主题
- Atlas：放 MOC、索引、结构图和全局导航
- Extras：存放附件、模板、图片等支撑材料

ACCESS 的价值不在名字，而在它让不同类型的材料有不同的落点。

## MOC 负责局部地图

MOC 是 Map of Content，也就是内容地图。

如果说文件夹解决“放在哪里”，MOC 解决“它们之间是什么关系”。一个 MOC 可以连接散落在不同文件夹里的笔记，并补充主题说明、阅读顺序、关键问题和后续待补内容。

我更愿意把 MOC 当成主题工作台：

- 定义一个主题的边界
- 聚合相关笔记
- 暴露知识缺口
- 帮助未来的自己快速恢复上下文
- 为公开页面提供目录

## 我的分工规则

文件夹只做粗分，不追求完美分类。  
标签主要表达状态、来源或特殊用途，不承担全部组织责任。  
链接负责表达真实关系。  
MOC 负责把关系整理成可读路径。  

新笔记尽量不要孤立创建。它至少应该连接到一个 MOC、一个来源、一个项目或一条相关概念。
