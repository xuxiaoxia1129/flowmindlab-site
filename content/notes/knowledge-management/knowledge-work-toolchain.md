# 辅助知识工作的工具链

Obsidian 是我的文本知识库核心，但它不需要承担所有事情。

工具链的设计重点，是让每个工具做自己擅长的部分。

## 捕捉工具

快速捕捉适合用低摩擦工具。

可能是手机备忘录、微信收藏、浏览器剪藏、flomo、Cubox，也可能只是 daily note。

关键是别让捕捉动作太重。灵感出现时，先收下来，后面再决定是否进入正式知识库。

## 阅读工具

阅读工具负责处理原材料。

文章、书籍、网页、视频笔记都可以先留在原工具里。进入 Obsidian 前，最好已经有一点自己的判断。

我更关心：

- 这份材料解决什么问题
- 有没有值得转成卡片的观点
- 是否需要进入某个 MOC
- 未来会不会出现在公开文章里

## 编辑工具

Obsidian 适合日常写作。

VS Code 更适合批量编辑、全局搜索、正则替换、路径调整和大规模重构。

当知识库越来越大，编辑工具的选择会直接影响维护效率。能用文本文件配合多种编辑器，是 Markdown 本地库的优势。

## 发布工具

Quartz 负责把整理后的 Markdown 变成网站。

GitHub 负责版本管理和自动部署。GitHub Pages 负责托管。自定义域名负责稳定入口。

这条链路足够轻，适合长期维护。

## AI 工具

AI 更适合做辅助整理：

- 归类素材
- 发现重复内容
- 改写旧句子
- 检查链接和结构
- 生成初版目录

但最终判断仍然要回到自己：哪些内容值得公开，哪些只是素材，哪些表达不像自己。
